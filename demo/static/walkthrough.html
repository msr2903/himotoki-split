0 · Orientation

What is this project?

Japanese text has no spaces. himotoki-split guesses where words start — like drawing bars between characters.

Input
猫が食べる
Model output
猫 が 食べる

Himotoki (the big teacher) also returns readings & meanings (~1.8 GB). This student only does splits, in a few megabytes.

1 · Repo map

Where things live

You don’t need every file. Follow this path:

  1. data/labels/*.jsonl Sentences + gold-ish segments from the teacher (Himotoki).

2 · Evaluation for beginners

How to read eval numbers

After training we ask: “On sentences the model never trained on, how good are the splits?”

Boundary F1

—

Think “how often did we put a cut in the right place?”
Ranges 0 → 1. Higher is better.

0.97 = excellent character-boundary skill. Small changes (0.970 → 0.972) still matter.

Exact-seg

—

“Was the entire sentence split perfectly?” One wrong cut → counts as fail.

Much harder than F1. ~45% on clean wiki text is solid; everyday short sentences feel better than this number suggests.

Two test sets (don’t mix them up)

SetWhat it isWhy it exists
holdout.jsonl (5k) Frozen random wiki sentences Apples-to-apples compare across experiments
holdout_clean.jsonl (~800) Shorter, less markup junk Closer to “real product” quality

Mini example

Gold: 今日 | は | 天気 | が | いい

Pred: 今日 | は | 天気がいい

  • Exact-seg → fail (not identical)
  • Boundary F1 → still fairly high (many cuts agree)

That’s why F1 can look great while exact-seg looks “low.”

What “good enough” looks like

  • Ship / demo F1 ≥ 0.97 on clean
  • Useful product exact ≥ 60–70% on clean
  • Strong exact ≥ 80% on a hand-checked gold set

You’re past the ship bar on F1; exact is the climb still ahead.

3 · Training results

How to read a training run

Training prints one line per epoch (one full pass over the data). 

epoch 1/6 loss=0.1780 val_f1=0.9530 val_exact=0.2690
epoch 2/6 loss=0.1049 val_f1=0.9656 val_exact=0.3530
epoch 6/6 loss=0.0594 val_f1=0.9824 val_exact=0.5570

loss ↓

Training error. Should fall over epochs. If it stalls high, learning isn’t working.

val_f1 ↑

F1 on a slice of train used as a progress check. Optimistic — not the real holdout.

val_exact ↑

Exact-seg on that same slice. Often much higher than holdout exact (data leakage-ish).

Rule of thumb: never celebrate val_* alone. Always run scripts/eval_model.py on the frozen holdout / clean set. Those numbers in output/eval_*.json are the ones that count.

Files to open after a run

  1. output/neural_train_metrics.json Epoch logs, sentence count, hyperparameters.
  2. output/eval_metrics_*.json Holdout + clean F1 / exact for a specific model.
  3. output/phase_*_summary.json Short story of a whole phase (A/B/C/active).
  4. output/active_query_summary.json What active learning tried and which model won.

5 · Cheat sheet

Commands you’ll actually use

# Try one sentence (CLI)
himotoki-split "猫が食べる"

# Score the shipped ONNX model
python scripts/eval_model.py -m himotoki_split/models/default.onnx \
  -i data/labels/holdout.jsonl --clean data/labels/holdout_clean.jsonl

# Active-query retrain (needs Himotoki DB)
python scripts/active_query_train.py --query-k 500 --upsample 5 --train

# This demo
python -m demo.app   # → http://127.0.0.1:8765
